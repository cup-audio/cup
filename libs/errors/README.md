# Errors

Runtime-independent error helpers shared by the Worker, the API server, Durable Objects, and the conversion workflows.

- [`describeExceptionChain`](src/exception-chain.ts) describes a caught error as telemetry reports it: its root cause, the innermost value of its `cause` chain, with type, message and stack, plus the wrapper types from outermost to innermost. Only Cup's own errors keep their message (`isCupError`): plain `Error`s and the subclasses listed in `CUP_ERROR_CLASS_NAMES`. A foreign error, such as Drizzle's query error that embeds SQL parameters, keeps its type and loses its message, also from the first line of its stack. Add a new Cup error subclass to that list, or its message is dropped. A cause chain that loops back on itself ends at the last error before the repetition. The log-event helper of [`@cup/telemetry.cloudflare`](../telemetry.cloudflare/README.md) sends the result with every logged error, and the server `beforeSend` applies the same rule to captured errors through `findErrorChain`, `findErrorType` and `isCupError`.
- [`assertUnreachable`](src/assert-unreachable.ts) ends an exhaustive `switch` or if-chain over a union: a missed case fails to compile, and an unexpected runtime value throws with its JSON instead of taking a silent fallback. Keep a fallback that is the specified behavior, such as tolerating unknown values at the listener API under [ADR 0010](../../docs/adr/0010-tolerate-unknown-keys-at-the-listener-api.md).

This library has no runtime dependencies and imports no other Cup package, so every package can depend on it without creating a dependency cycle.
