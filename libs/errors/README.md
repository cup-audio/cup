# Errors

Runtime-independent error helpers shared by the Worker, the API server, Durable Objects, and the conversion workflows.

- [`describeExceptionChain`](src/exception-chain.ts) describes a caught error as telemetry reports it: its root cause, the innermost value of its `cause` chain, with type, message and stack, plus the wrapper types from outermost to innermost. Only Cup's own errors keep their message (`isCupError`): instances of [`CupError`](src/cup-error.ts), the base class of every error Cup throws in Worker code, and errors a Durable Object RPC call rebuilt from one, since the brand is an own property that the call keeps. Every other error, a plain `Error` from a dependency included, is foreign: like Drizzle's query error that embeds SQL parameters, it keeps its type and loses its message, also from the first line of its stack. Throw `CupError`, or a subclass of it, for a message that telemetry should keep. A Workflow step rebuilds a failed step's error as a plain `Error` without own properties, so the Workflow runs capture the error their step threw instead, and only a rebuilt error that a replayed run gets after an engine restart counts as foreign ([capture rule](../../docs/architecture/observability.md#capture-rule)). A cause chain that loops back on itself ends at the last error before the repetition. The log-event helper of [`@cup/telemetry.cloudflare`](../telemetry.cloudflare/README.md) sends the result with every logged error, and the server `beforeSend` applies the same rule to captured errors through `findErrorChain`, `findErrorType` and `isCupError`.
- [`assertUnreachable`](src/assert-unreachable.ts) ends an exhaustive `switch` or if-chain over a union: a missed case fails to compile, and an unexpected runtime value throws with its JSON instead of taking a silent fallback. Keep a fallback that is the specified behavior, such as tolerating unknown values at the listener API under [ADR 0010](../../docs/adr/0010-tolerate-unknown-keys-at-the-listener-api.md).

This library has no runtime dependencies and imports no other Cup package, so every package can depend on it without creating a dependency cycle.
