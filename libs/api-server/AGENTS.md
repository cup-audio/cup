# API server

## Layout

`src/index.ts` is the package entry (the `.` export in `package.json`); `createApiServer` in `src/api-server.ts` composes the listener and operator routes, middleware, and handlers with Hono from the folders below. `src/api-server-environment.ts` declares the Worker bindings and settings the server reads (`ApiServerEnvironment`) and imports nothing else from the package. The folders:

- `http/`: the HTTP concerns that `api-server.ts` uses, such as token verification, signed media URLs, error responses, and delivery. `MEDIA_URL_SIGNING_KEY` signs both signed media URLs and signed position URLs, which differ only in the token's `purpose` (`http/signed-media-url.ts`); keep tokens without a purpose byte-identical. It may import `adapters/`, `use-cases/`, and the environment, never `src/index.ts` or `src/api-server.ts`.
- `use-cases/`: the application rules, without Hono or bindings, that receive their Durable Object, storage, and adapter calls as dependency arguments, such as the Apple confirmation of a deletion and the revocation of Apple sign-ins during one (`use-cases/apple-credential-revocation.ts`), and which provider confirms a deletion (`use-cases/confirmation-provider.ts`). It imports neither `http/` nor `src/index.ts` or `src/api-server.ts`.
- `adapters/`: calls to other bindings and services: conversion readers and conversion dispatch over the owning account or grant Durable Object, the Supabase admin user lookup (`adapters/supabase-user.ts`), and, on top of that lookup, Google token revocation through Google and Apple sign-in revocation through Apple. It may import the environment, never `http/`, `use-cases/`, `src/index.ts`, or `src/api-server.ts`.

Tests stay flat in `test/`. Vitest runs the files without isolation, so tests mock no modules: they sign real account tokens with `test/account-tokens.ts`, stub `fetch` for the key set and providers, record Sentry exceptions and log events with `test/sentry-recorder.ts`, and give each file its own `SUPABASE_URL`, because `http/account-auth.ts` caches the key set per issuer. `vitest.config.ts` aliases `cloudflare:workers` to `test/cloudflare-workers-stub.ts`, so the Durable Object modules load in Node. [`oxlint.config.ts`](oxlint.config.ts) enforces these import directions with `no-restricted-imports`; place a new file in the folder of its role, and extend the overrides there when you add a folder.
