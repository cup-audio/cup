# Generate migrations, schema diagrams and brand assets deterministically

Several checked-in files are generated by repository tools: the stores' SQLite migrations and their schema diagrams ([drizzle-migrations](../../tooling/drizzle-migrations)) and the brand assets ([brand-assets](../../tooling/brand-assets)). The shared migration generator came with [#26](https://github.com/cup-audio/cup/pull/26), the schema diagrams with [#51](https://github.com/cup-audio/cup/pull/51) and the Mermaid Live links with the redraw of the runtime map; the brand asset generator came with the adoption of Cup's branding. Generated files are checked for staleness, so they must come out the same on every machine and fail loudly rather than drift. These decisions were recorded from code comments on 2026-11-23.

## Decision

- [generate-migrations.ts](../../tooling/drizzle-migrations/src/generate-migrations.ts) runs the calling package's `drizzle-kit` devDependency, which its migration tests also use.
- Drizzle Kit gives a custom migration a copy of the previous snapshot. The handwritten SQL must produce the current schema, so the generator records that schema as the snapshot for later diffs.
- [schema-diagram.ts](../../tooling/drizzle-migrations/src/schema-diagram.ts) renders each store's entity-relationship diagram into [durable-object-storage.md](../architecture/durable-object-storage.md). A diagram names every table and draws one line per declared foreign key, from the referenced table to the referencing one, labelled with the referencing columns; columns stay in the schemas. A relationship is one-to-one when the foreign key columns identify a referencing row uniquely. A partial unique index does not make it one-to-one, since it allows duplicates outside its condition.
- Names are sorted with `sort()` without a comparator, which orders by code unit, so the page does not depend on the locale.
- Each diagram gets a Mermaid Live link. Mermaid Live reads its editor state from the URL fragment as zlib-deflated, base64url-encoded JSON, and the state matches the links next to the hand-written diagrams in `docs/architecture`.
- The [brand asset generator](../../tooling/brand-assets/src/cli.ts) rejects source artwork that Android's vector format cannot represent, rather than silently dropping shapes when the source icon changes.

## Consequences

- A custom migration's snapshot reflects the schema files, not the SQL, so the two must agree.
- A source icon using unsupported SVG features fails the brand-assets sync instead of producing a degraded Android icon.
