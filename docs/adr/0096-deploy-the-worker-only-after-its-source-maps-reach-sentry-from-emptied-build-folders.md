# Deploy the Worker only after its source maps reach Sentry, from emptied build folders

A release whose source maps are missing in Sentry reports unreadable stack traces until the next deploy, and a build folder that still holds an earlier build's files would upload and deploy them too. The [deploy script](../../apps/cloudflare-worker/scripts/deploy.ts) came with [cup-audio/cup#422](https://github.com/cup-audio/cup/pull/422), the observability spec [cup-audio/cup#403](https://github.com/cup-audio/cup/issues/403) for Linear CUP-37; [cup-audio/cup#452](https://github.com/cup-audio/cup/pull/452) added emptying the build folders, and commit 917158c6 kept `.dev.vars` out of the Turbo cache. The local development checks date from [cup-audio/cup#74](https://github.com/cup-audio/cup/pull/74), and the session-start hook's checkout rule from commit aed7b183 (bootstrap fresh worktrees during install). These decisions were recorded from code comments on 2026-11-23.

## Decision

- **No release goes live without its source maps in Sentry.** The deploy checks Sentry auth, empties the build folders, builds, uploads the web and Worker source maps, and only then runs `wrangler deploy`. Any failing step aborts before anything goes live; there is deliberately no flag to deploy anyway. The upload token lives in `~/.sentryclirc` from `sentry-cli login`, and `sentry-cli info` fails without it. The script runs from the Worker's directory through `pnpm run deploy`, which puts the package's binaries on `PATH`.
- **Source maps are matched by debug ID, not release.** `prepare-source-maps` in each package's `turbo:build` injects debug IDs and moves the maps out of the deployed bundle (the Worker builds with `sourcemap: "hidden"`, [Vite config](../../apps/cloudflare-worker/vite.config.ts)), and the upload names no release. Rolldown's runtime and preload helpers have no source map; every other web chunk has one ([build output test](../../apps/cloudflare-worker/test/web-app-build-output.test.ts)). Source maps go to Sentry, not to Cloudflare (`upload_source_maps: false`, [ADR 0030](0030-observe-production-with-sentrys-own-sdks-and-turn-cloudflares-observability-off.md)).
- **The served build folders are emptied before the build.** Turbo restores a cached build by writing its files over what a folder already holds and removes none, so without emptying them first the upload and the deploy would carry the files of every earlier build. Only the served build and its maps go; the declaration output and its build info stay together, so TypeScript's incremental build keeps working.
- **The Worker never builds without the web app.** The Worker serves the web app's build output as its static assets, and `cap sync` packs the same directory into the shells; the web package builds first through Turbo (`^turbo:build`), and the Worker build fails when its `index.html` is missing.
- **The Sentry Vite plugin adds build-time instrumentation only** (Hono and `openai` spans) and uploads no source maps. [`src/index.ts`](../../apps/cloudflare-worker/src/index.ts) wraps the entry points itself, so that the integration tests, which bundle without Vite, run the same wrapping ([ADR 0030](0030-observe-production-with-sentrys-own-sdks-and-turn-cloudflares-observability-off.md)).
- **`.dev.vars` stays out of the Turbo cache** ([`turbo.jsonc`](../../apps/cloudflare-worker/turbo.jsonc)). The Cloudflare Vite plugin copies the Git-ignored `.env.local` into it; it holds secrets and goes stale, and `wrangler deploy` does not upload it.
- **Tests' inputs outside the package are Turbo inputs:** `wrangler-config.test.ts` checks the Supabase site URL in `terraform/production/supabase.tf`, and `deploy.test.ts` the repository's Sentry CLI config.
- **Worker types are generated, not committed**, so every task that typechecks waits for `turbo:cf-typegen`, in the Worker and in [`@cup/rolling-limits`](../../libs/rolling-limits/turbo.jsonc). The rolling-limits [Wrangler config](../../libs/rolling-limits/wrangler.test.jsonc) only generates the Durable Object runtime types the limiter compiles against; no Worker runs it.
- **Local development fails early on a stale `.env.local`.** A stale `.env.local` can point at a local Supabase stack that is no longer running; the server would start, and sign-in would fail only later in the browser, so the dev server checks that local Supabase is reachable at startup. The local test account vars in [`wrangler.jsonc`](../../apps/cloudflare-worker/wrangler.jsonc) are empty defaults: `pnpm dev:services` overrides them in `.env.local`, the Worker ignores them unless `LOCAL_DEVELOPMENT` is `"true"` ([ADR 0012](0012-offer-a-local-test-account-instead-of-google-in-development.md)), and local development loads only declared keys, so they need the empty defaults.
- **The Claude Code session-start hook runs from the session's checkout** ([`session-start.sh`](../../.claude/hooks/session-start.sh)), the Git top level, because in a worktree session it differs from the project directory.

## Consequences

- Deploying needs `sentry-cli login` on the deploying machine; [`deploy.test.ts`](../../apps/cloudflare-worker/test/deploy.test.ts) checks that a missing token aborts before building.
- `vite preview` after a cache hit runs without `.dev.vars` until the next real build.
