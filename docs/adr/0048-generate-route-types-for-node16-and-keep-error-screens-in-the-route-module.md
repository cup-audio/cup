# Generate route imports with extensions and keep error screens in the route module

The web app's routes are generated by TanStack Router's Vite plugin, which writes the route tree and splits route code into chunks. Two plugin defaults did not fit: its extensionless imports, and splitting the error screen. [cup-audio/cup#6](https://github.com/cup-audio/cup/pull/6) restored the route types, and [cup-audio/cup#165](https://github.com/cup-audio/cup/pull/165) changed the code splitting. These decisions were recorded from code comments on 2026-11-23.

## Decision

- The [shared Vite configuration](../../apps/web-app/vite.shared.ts) has the plugin add `.js` extensions to the generated route tree's imports. The app typechecks with `moduleResolution: node16`, which cannot resolve extensionless imports; the generated tree carries `@ts-nocheck`, so unresolved route imports would silently degrade every route type to `any`.
- Code splitting splits `component` and `notFoundComponent`, the plugin's default minus `errorComponent`, which stays in the eagerly loaded route module. The router loads a split error screen only when a loader fails, so a query failing during render would first suspend on the chunk: the pending component flashes and React warns about `use()`.

## Consequences

- Route types stay checked although the generated tree is excluded from type checking.
- Every route's error screen ships in its route module, so it shows without a chunk download.
