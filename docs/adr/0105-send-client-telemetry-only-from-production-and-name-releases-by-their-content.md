# Send client telemetry only from production, and name releases by their content

The web app and both Capacitor shells run one `@sentry/capacitor` with `@sentry/react` bundle ([ADR 0030](0030-observe-production-with-sentrys-own-sdks-and-turn-cloudflares-observability-off.md)), the shells with Sentry's native SDKs under [ADR 0031](0031-capture-native-crashes-in-the-shells-without-consent-keeping-no-installation-id-on-the-device.md). The same production bundle also runs in every E2E suite and in debug builds, which must send nothing. These decisions were made with the observability spec [cup-audio/cup#403](https://github.com/cup-audio/cup/issues/403) for Linear CUP-37 and implemented in [cup-audio/cup#422](https://github.com/cup-audio/cup/pull/422). They were recorded from code comments on 2026-11-23.

## Decision

- **The on/off rule** ([client Sentry options](../../libs/telemetry.browser/src/client-sentry-options.ts)): the browser sends only from `https://cup.audio`; a release shell sends only when its API origin is `https://cup.audio`; a debug shell sends nothing, unless the mobile E2E suite passed it a test DSN (the Sentry stub's, as the `cupTestSentryDsn` launch argument), and then only to that DSN. `https://cup.audio` is the only origin, because every E2E suite runs the production bundle elsewhere. A shell counts as a release build only when its native side says `release` explicitly, so a shell that says nothing is a debug build and sends nothing.
- **The crash-report switch keeps JS telemetry.** With the shell's "Send crash reports" switch off, which the native `CrashReporting` plugin keeps, the shell runs JS-only: its JS errors still go through the tunnel, but the native SDK stays off.
- **Web releases are named by content** ([web release plugin](../../libs/telemetry.browser/src/web-release.vite.ts)): `web@<content hash of the entry chunk>`, the first 16 characters of its SHA-256, enough to tell bundles apart in Sentry's release list, in a `<meta name="cup-release">` of the built `index.html`, which [`readWebRelease`](../../libs/telemetry.browser/src/web-release.ts) reads at runtime. The entry chunk imports every other chunk by its hashed file name, so the hash changes exactly when the bundle's code does: an unchanged bundle keeps its release, and Turbo can replay E2E suites that ran it. The release cannot live in the entry chunk itself, whose hash would then depend on it. Under Vite's development server the page has no release.
- **Shell releases name the app version.** A shell's release is `audio.cup.app@<version>+<build>` with the build as `dist`, and the native SDK gets the same release, so a native crash and the JS error before it line up; the web bundle goes along as `cup.web_release`.
- **The client leaves `dataCollection` unset**, because setting any of its keys makes the others permissive.
- **Traces are sampled by a sampler, not `tracesSampleRate`**, because the Capacitor SDK bridges a sample rate to the Cocoa SDK, which would turn on all of its automatic tracing.
- **Requests to the Listener API join the Worker's trace**; no other host gets trace headers.
- **Native capture follows the crash-report switch**: native crashes, ANRs and app hangs are captured, with the native installation ID kept in memory only ([ADR 0031](0031-capture-native-crashes-in-the-shells-without-consent-keeping-no-installation-id-on-the-device.md)), unless the listener turned crash reports off. That gives up native release health, so native session tracking is off.
- **Known browser noise is ignored**: a `ResizeObserver` loop the browser recovers from itself, and a request aborted on navigation, which rejects with an `AbortError`. Sentry matches a string anywhere in the message, so each pattern is an anchored regular expression. A request that fails for another reason, such as a dropped connection, is still captured when nothing handles it.
- **Integrations are added to the Capacitor SDK's defaults**: span streaming, which the browser SDK needs to stream spans, and TanStack Router tracing, which names page-load and navigation spans after the routes. Zod errors, console capture, feedback, view hierarchy, profiling, CapacitorHttp tracing and replay are not among the defaults and stay off.
- **Supabase adds spans and breadcrumbs only** ([Supabase integration](../../libs/telemetry.browser/src/supabase-telemetry.ts)). The web app's Supabase client exists only once account auth loads its configuration, so the integration is added then with `Sentry.addIntegration`. It sends no query data, and the client `beforeSend` drops the errors it captures from failed auth calls (mechanism `auto.db.supabase.auth`), because the web app handles those failures itself.
- **iOS native options**, set through the workspace's patch of `@sentry/capacitor` (Android sets the same in its manifest): native spans of view controllers with frames tracking, which automatic performance tracing carries, and no network, file, Core Data or user-interaction spans. MetricKit is on, because Cocoa's crash handler reports uncaught NSExceptions on iOS; Cocoa's option of that name is macOS's. App-hang tracking and network breadcrumbs keep Cocoa's defaults, both on.
- **A lost WebView page is reported once** ([WebView process loss](../../libs/telemetry.browser/src/webview-process-loss.ts)). When a shell's WebView loses its page (on Android its renderer process is gone, on iOS its WebContent process terminated), the native side records it and brings the page back. The web app takes the recorded loss when it starts, which forgets it, so each loss is reported once, as one error event whose fixed fingerprint per platform groups every loss into one issue.

## Consequences

- No E2E suite, debug build or local development run sends to production Sentry.
- A content-identical web build keeps its release across rebuilds.
