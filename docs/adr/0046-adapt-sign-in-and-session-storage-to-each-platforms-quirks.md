# Adapt sign-in and session storage to each platform's quirks

The web app signs in and keeps the account session through one platform adapter per runtime: the web, the Android shell and the iOS shell. Google Play services, Supabase, the iOS Keychain and Capacitor each behave in ways the adapters must absorb. [cup-audio/cup#230](https://github.com/cup-audio/cup/pull/230) made a cancelled Android sign-in a cancellation, [cup-audio/cup#227](https://github.com/cup-audio/cup/pull/227) (CUP-60) moved iOS sign-in to a system browser sheet ([ADR 0019](0019-sign-in-on-ios-through-supabase-oauth-in-a-system-browser-sheet.md)), [cup-audio/cup#256](https://github.com/cup-audio/cup/pull/256) (CUP-44) set the Keychain accessibility and ignored `chooseAccount` on Android, the commit "feat(accounts): add social signup and account lifecycle" added the fresh-authentication check, and "feat(mobile-app): add iOS sharing and Universal Links" and [cup-audio/cup#101](https://github.com/cup-audio/cup/pull/101) added share intake. The [authentication architecture](../architecture/authentication.md) describes the resulting behaviour. These decisions were recorded from code comments on 2026-11-23.

## Decision

- **Android cancellation.** The [Android adapter](../../apps/web-app/src/platform/account-auth.android.ts) treats only some messages of the Google sign-in plugin's cancellation code as the person backing out: Google Play services' detail when the person leaves its add-account or account-picker screen, and the plugin's own message when Google gives no detail. Google Play services reports some failures, such as a missing Android OAuth client ("[16] Account reauth failed."), with the same code. A cancellation rejects with `SignInCancelledError`; any other plugin failure with a `UserFacingError`. For a `SignInCancelledError` ([errors](../../apps/web-app/src/errors.ts)), screens that only offer sign-in show nothing, because the person chose it; a step that needed the sign-in, such as confirming account deletion, says why it stopped. The cancellation code is `ErrorCode.SignInCanceled`, which only the plugin's lazily loaded module provides, so it is passed in.
- **Android account picker.** The Android adapter ignores `chooseAccount`: sign-out already ends the device's Google sign-in (`clearNativeSignIn`), so Credential Manager shows its account picker on the next sign-in anyway.
- **iOS Keychain accessibility.** The [iOS adapter](../../apps/web-app/src/platform/account-auth.ios.ts) writes the session's Keychain items readable after the device's first unlock instead of only while it is unlocked: a token refresh during background audio with the screen locked can then read the session and persist the rotated refresh token. Items written before keep their accessibility (the plugin's default, `whenUnlocked`), stay readable, and take the new one on their next write, the session's next refresh. Android ignores the access option ([native storage tests](../../apps/web-app/src/platform/account-auth.native.test.ts)).
- **Secure Storage in both shells.** Both shells keep the session in Secure Storage, so the platform's keychain or keystore protects it ([native adapter](../../apps/web-app/src/platform/account-auth.native.ts)).
- **iOS OAuth callback.** Supabase sends the browser back after Google to the app's own scheme, which the native `WebAuthentication` plugin waits for; Supabase's redirect allow-list must contain it. The `ASWebAuthenticationSession` shares Safari's cookies and resolves with the `audio.cup.app:` URL the sign-in ended at. Supabase puts an error description in the callback URL's query or its fragment, so the adapter reads both.
- **Fresh authentication.** Supabase AMR timestamps have whole-second precision, so a confirmation requires authentication strictly after the confirmation was issued ([account confirmation](../../apps/web-app/src/data-fetching/account-confirmation.ts)). The Google provider token lives only on the session; `requestApi` re-resolves its own token and guard, so the confirmation's own check of the fresh session's subject exists to name the account mismatch and to narrow `session`.
- **Incoming URLs.** On iOS, a launch URL may also arrive as an event while the listener is registering, so the launch URL is handled only when no event arrived ([incoming URLs](../../apps/web-app/src/platform/incoming-urls.ios.ts)). In [share intake](../../apps/web-app/src/platform/share-intake.ts), a form that mounts before the previous one unmounts has already replaced the listener, so the older form's cleanup leaves it in place.

## Consequences

- A new Google Play services cancellation message counts as a failure until it is added to the list.
- Supabase's redirect allow-list is part of the iOS sign-in's configuration ([Terraform guide](../../terraform/README.md#google-sign-in-configuration)).
- Sessions stored before the accessibility change migrate on their next refresh, so an update signs nobody out.
