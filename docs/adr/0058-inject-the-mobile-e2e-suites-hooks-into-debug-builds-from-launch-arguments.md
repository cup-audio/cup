# Inject the mobile E2E suite's hooks into debug builds from launch arguments

[ADR 0018](0018-test-the-mobile-apps-with-appium-through-webdriverio-on-host-owned-emulators-and-simulators.md) made the debug build the test build: the mobile E2E suite launches it with the test Worker's origin as a launch argument, only debug native code reads it, and release builds carry none of it. The hooks grew with the suite: a fake Google sign-in in [cup-audio/cup#211](https://github.com/cup-audio/cup/pull/211), an audio focus probe and shortened media session timings with the native Android player in [cup-audio/cup#401](https://github.com/cup-audio/cup/pull/401), and a Sentry stub DSN and a renderer crash with native crash reporting in [cup-audio/cup#422](https://github.com/cup-audio/cup/pull/422). The [bundle safety check](0065-shrink-android-release-bundles-with-r8-and-check-them-before-upload.md) keeps them out of release bundles. These decisions were recorded from code comments on 2026-11-23; the mobile app README's "Debug launch arguments" and "iOS debug launch arguments" sections list the arguments.

## Decision

### Android: a debug source set

- Every hook lives in the debug source set (`android/app/src/debug`), so the main sources and release builds stay free of test hooks. Its [manifest](../../apps/mobile-app/android/app/src/debug/AndroidManifest.xml) adds the [debug application](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/DebugApplication.java) and its [network security config](../../apps/mobile-app/android/app/src/debug/res/xml/network_security_config.xml): the suite's test Worker and fake auth provider serve plain HTTP on `localhost`, and its Sentry stub, which the native Sentry SDK sends to, on `127.0.0.1`. The debug-only `androidx.webkit` dependency provides the document-start script.
- `DebugApplication` reads the launch arguments, intent extras, around Capacitor's bridge creation. A malformed argument throws, which stops the app before it can reach production.
- [`TestApiOrigin`](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/TestApiOrigin.java) accepts nothing but `http://localhost:<port>`. With it, [`TestApiOriginPlugin`](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/TestApiOriginPlugin.java) points the web app at the test Worker before the page loads: it sets the global `apiOrigin()` reads, and with a Sentry stub DSN the global the web app's telemetry reads, so the telemetry, and through it the native Sentry SDK, sends only there; it also lets the `https://localhost` page load `http://localhost` media. Capacitor loads plugins after creating the WebView and before loading the page. Capacitor logs and ignores plugin load errors, so the plugin crashes the app instead of letting it talk to production.
- [`TestSentryDsn`](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/TestSentryDsn.java) accepts only `http://<key>@127.0.0.1:<port>/<project>` and only next to a test API origin, whose telemetry tunnel the web app sends through. The stub listens on the host's `127.0.0.1`, which `adb reverse` maps onto the device's. Without it, a debug build sends nothing to Sentry.
- [`FakeGoogleSignInPlugin`](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/FakeGoogleSignInPlugin.java) replaces the Google sign-in plugin of the same name when the suite launches the app with a test origin: `signIn` returns an ID token from the suite's fake auth provider that carries the hashed nonce it was given, so the web app's unchanged sign-in runs against the test Worker without Google. The fake auth provider's origin is the `supabaseUrl` of the test Worker's auth configuration. The plugin reads the origin at load from the launch intent, since a later intent, such as a share, carries no origin, and it sends plain HTTP only to `localhost`. Capacitor registers the plugins it found after those registered before `onCreate`, so the fake replaces the real plugin only once the bridge exists; the web app calls the plugin by name, so its calls reach the fake from then on. A launch argument keeps the real plugin with the test origin, so a test can open Google's real add-account screen.
- [`FocusProbePlugin`](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/FocusProbePlugin.java) takes audio focus from Cup's player on an adb broadcast, the way a call (`transient`), a navigation prompt (`duck`) or another media app (`full`) would, and `abandon` gives it back, so the suite can check how ExoPlayer reacts without real apps. Its receiver is registered only while the app runs with the test API origin, and is exported because adb broadcasts come from the shell.
- [`TestPlaybackTimings`](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/TestPlaybackTimings.java) passes shortened media session timings as intent extras with the test origin, so the suite's lifecycle cases finish in seconds: how long the plugin treats the URLs as valid, matching the test Worker's signed URL lifetime, and Media3's foreground grace after a pause, about 10 s instead of 10 minutes. They take effect for the next load and the next start of the service; a launch without them restores the release values, which [`PlaybackTimings`](../../apps/mobile-app/android/app/src/main/java/audio/cup/app/PlaybackTimings.java) keeps for release builds.
- [`TestRendererCrashPlugin`](../../apps/mobile-app/android/app/src/debug/java/audio/cup/app/TestRendererCrashPlugin.java), registered with a test API origin, lets the suite crash the WebView's renderer process, as `WebViewProcessLoss` handles it. It answers the call first, because the page that called it dies with its renderer.

### iOS: `#if DEBUG` code in the main view controller

- The test origin is the defaults key `cupTestApiOrigin`. The process arguments `-cupTestApiOrigin <origin>` set it for one launch, through the defaults' arguments domain. A launch without arguments, such as one a shared URL starts, reads the value the suite wrote into Cup's own defaults with `xcrun simctl spawn <simulator> defaults write audio.cup.app cupTestApiOrigin <origin>`. Anything but `http://localhost:<port>` stops the app.
- The Sentry stub's DSN is the defaults key `cupTestSentryDsn`, set through `-cupTestSentryDsn <dsn>`; it must be `http://<key>@127.0.0.1:<port>/<project>` and needs a test API origin. The stub listens on the host's `127.0.0.1`, which the simulator shares. Without it, a debug build sends nothing to Sentry. Both values stop the app when malformed, before it can reach production.
- The [main view controller](../../apps/mobile-app/ios/App/App/MainViewController.swift) injects a document-start user script that sets the same globals as on Android. Capacitor replaces the configuration's content controller while preparing the WebView, so the script is added in `capacitorDidLoad`, after the bridge exists and before `viewDidLoad` loads the page. Both values are validated to contain no characters that need escaping in a string literal. ATS's built-in exemption for `localhost` allows the plain HTTP.
- The [web authentication plugin](../../apps/mobile-app/ios/App/App/WebAuthenticationPlugin.swift) opens HTTPS only, except that a debug build also signs in at the suite's fake auth provider on `http://localhost`.

## Consequences

- Each new hook must live in the debug source set on Android or under `#if DEBUG` on iOS, and accept only loopback values, so that a debug build pointed anywhere else fails instead of reaching production.
- `android:release` passes the bundle safety check the classes of the debug source set, so a new Android hook placed there is refused in a release bundle.
