# Optional settings and integrations of Cup's Sentry SDKs

Research date: 2026-11-16, for [issue #393](https://github.com/patricktree/cup/issues/393) of the [map: observability and APM](https://github.com/patricktree/cup/issues/337), as input for [Which optional Sentry SDK settings and integrations does Cup turn on?](https://github.com/patricktree/cup/issues/394). Everything below was read from the published npm packages (`@sentry/cloudflare`, `@sentry/core` and `@sentry/server-utils` 11.12.0; `@sentry/capacitor` 4.6.0; `@sentry/browser`, `@sentry/core` and `@sentry/react` 10.76.2) and from the native SDK sources at the tags that `@sentry/capacitor` 4.6.0 pins: `sentry-android` [8.64.0](https://github.com/getsentry/sentry-capacitor/blob/4.6.0/android/build.gradle) and `sentry-cocoa` [9.28.0](https://github.com/getsentry/sentry-capacitor/blob/4.6.0/Package.swift). Quota categories come from [Sentry's pricing page](https://sentry.io/pricing/) and [quota docs](https://docs.sentry.io/pricing/quotas/), read the same day. Nothing was run; where a claim depends on runtime behaviour that the earlier hands-on probes did not cover, it says so.

## Question

For each Sentry SDK Cup runs, at the versions the map decided, which optional settings and integrations exist beyond the defaults, what does each one send or change, and what does it cost in quota, bundle size, runtime overhead or privacy?

## Answer

- **The Worker SDK is a major ahead of what several map decisions assume.** [Verify Sentry's SDKs hands-on](https://github.com/patricktree/cup/issues/350) pinned `@sentry/cloudflare` 11.12.0, but [Which backend and alert channel?](https://github.com/patricktree/cup/issues/342) and [How are Cup's Sentry SDKs wired](https://github.com/patricktree/cup/issues/378) configure it with v10 options. In v11, `sendDefaultPii` and `enableLogs` are gone, and an unset `dataCollection` is **more permissive** than v10's `sendDefaultPii: false`: user info (client IP inference), cookies, all request and response headers, incoming request bodies up to 10 KB, database query data and gen-AI inputs and outputs are collected by default ([v11 migration guide](https://github.com/getsentry/sentry-javascript/blob/11.12.0/MIGRATION.md#senddefaultpii-is-replaced-by-datacollection)). Cup has to set `dataCollection` explicitly in `@cup/telemetry.cloudflare`; `sendDefaultPii: false` there is at best a type error and at worst silently ignored.
- **Two Worker defaults reach narration-adjacent text.** The Cloudflare Vite plugin's build-time instrumentation (on by default) registers `openAIIntegration` for the `openai` package that content selection uses inside the preparation Workflow, and v11's default `dataCollection.genAI` records prompts and completions on spans. The default `httpServerIntegration` attaches the body of every non-GET Listener API request. Both conflict with the map's "no narration text" rule unless switched off.
- **v11 changes the span model.** Span streaming (`traceLifecycle: 'stream'`) is the default: `beforeSendSpan` receives a different shape, `beforeSendTransaction` and `ignoreTransactions` do nothing, and scope tags no longer reach spans, so `cup.conversion.id` must be set with `setAttribute`. Every Durable Object SQL statement and storage call is its own span, which drives span quota at the decided 1.0 trace rate.
- **The client (`@sentry/capacitor` 4.6.0 with `@sentry/browser` 10.76.2) still honours `sendDefaultPii: false`**, but setting any `dataCollection` key there switches every unset category to the permissive defaults. Its default integration list differs from `@sentry/browser`'s: in the browser it adds `browserSessionIntegration` (web release health, not billed), in the shells native session tracking and device contexts. JS breadcrumbs, tags, extras and the user are copied into the native scope, so only `beforeBreadcrumb`, not `beforeSend`, keeps unmasked URLs off native crash events.
- **The bridge passes only a few options to the native SDKs, and differently per platform.** Android receives none of `tracesSampleRate`, `sampleRate`, `sendDefaultPii` or `maxBreadcrumbs`; the manifest is the only way to set those. iOS receives `tracesSampleRate`, so a client trace rate of 1.0 also turns on Cocoa's automatic performance tracing (app start, view controller, network, file I/O spans) and none of its sub-switches can be reached from JS. Cocoa's network breadcrumbs (on by default) see every `CapacitorHttp` request.
- **Opt-in features with quota or privacy weight**: session replay (decided off), profiling (not on the free plan), screenshots and view hierarchies (browser and native; screenshots of the reader would show narration text), user feedback (name and email fields), `httpClientIntegration` and `enableCaptureFailedRequests` (decided off by [#349](https://github.com/patricktree/cup/issues/349)), `captureConsoleIntegration` (error quota), `extraErrorDataIntegration`, `supabaseIntegration` (the web app uses `@supabase/supabase-js`), Android `attach-threads`, ANR thread dumps and raw tombstones (attachments), and Cocoa MetricKit.

## How to read the checklists

Each row is one option or integration. "Default" says whether it is on without Cup doing anything, at the pinned version. "Quota" names the free Developer plan category it fills: errors (5k), spans (5M), logs (5 GB), application metrics (5 GB), replays (50), attachments (1 GB), cron monitors (1), uptime monitors (1); profiling hours are not included on the free plan; release health sessions are [not billed](https://docs.sentry.io/product/releases/health/) ([pricing](https://sentry.io/pricing/)). "PII" names the personal data it can carry. "Status" is **Decided** with the deciding ticket, **Open** for [#394](https://github.com/patricktree/cup/issues/394), or **N/A** when Cup does not use the feature.

Bundle sizes below are the gzipped `size-limit` budgets in the JavaScript SDK repository at [10.76.2](https://github.com/getsentry/sentry-javascript/blob/10.76.2/.size-limit.js): `@sentry/react` 35 KB, with tracing 54 KB; `@sentry/browser` with tracing 52 KB, plus profiling 57 KB, plus replay 91 KB, plus feedback 50 KB (without tracing), plus logs 35 KB, plus metrics 34 KB. Server bundle size matters less: the [#350 probe Worker](https://github.com/patricktree/cup/issues/350) was 108 KB gzipped with the SDK.

## `@sentry/cloudflare` 11.12.0 (Worker, Durable Objects, Workflows)

### Defaults Cup gets without asking

`getDefaultIntegrations` installs Dedupe, EventFilters, FunctionToString, ConversationId, LinkedErrors, Fetch, HttpServer, RequestData, Console, plus every integration that build-time instrumentation registered ([`baseSdk.js`](https://unpkg.com/@sentry/cloudflare@11.12.0/build/esm/prod/baseSdk.js)). The request wrapper also sets a `culture` context with the Cloudflare `timezone` and a `cloud_resource` context on every request ([`scope-utils.js`](https://unpkg.com/@sentry/cloudflare@11.12.0/build/esm/prod/scope-utils.js), [`wrapRequestHandlerWithInit.js`](https://unpkg.com/@sentry/cloudflare@11.12.0/build/esm/prod/wrapRequestHandlerWithInit.js)). The Vite plugin's `autoInstrumentation` wraps the entry, Durable Objects and Workflows, and its `buildTimeInstrumentation` injects diagnostics channels into supported dependencies; both default to `true` ([plugin types](https://unpkg.com/@sentry/cloudflare@11.12.0/build/types/vite/index.d.ts)). `withSentry` also proxies `env`: D1, KV, R2, Queue producers, the Workers AI binding, service bindings and Durable Object namespaces get spans ([`instrumentEnv.js`](https://unpkg.com/@sentry/cloudflare@11.12.0/build/esm/prod/instrumentations/worker/instrumentEnv.js)).

## `@sentry/capacitor` 4.6.0 with `@sentry/react` and `@sentry/browser` 10.76.2 (browser and both shells)

### What `Sentry.init(options, SentryReact.init)` installs

`@sentry/capacitor` replaces the browser defaults with its own list ([`integrations/default.js`](https://unpkg.com/@sentry/capacitor@4.6.0/dist/esm/integrations/default.js)): `capacitorRewriteFrames`, `nativeRelease`, `eventOrigin`, `sdkInfo`, EventFilters, FunctionToString, BrowserApiErrors, Breadcrumbs, GlobalHandlers, LinkedErrors, Dedupe; in the shells (`enableNative`) also `deviceContextIntegration` and `logEnricherIntegration`, in the browser `httpContextIntegration` and, while `enableAutoSessionTracking` is true (its default), `browserSessionIntegration`. Unlike plain `@sentry/browser` ([`sdk.js`](https://unpkg.com/@sentry/browser@10.76.2/build/npm/esm/prod/sdk.js)) it adds no `cultureContextIntegration` and no `conversationIdIntegration`. In the shells it also enables scope sync: every `setUser`, `setTag(s)`, `setExtra(s)` and `addBreadcrumb` is copied to the native scope after `beforeBreadcrumb` ran ([`scopeSync.js`](https://unpkg.com/@sentry/capacitor@4.6.0/dist/esm/scopeSync.js)), and `deviceContextIntegration` merges native contexts, user and breadcrumbs into each JS event ([`devicecontext.js`](https://unpkg.com/@sentry/capacitor@4.6.0/dist/esm/integrations/devicecontext.js)).

- Whether `sendDefaultPii` in the `defineCloudflareOptions` callback fails type checking (expected, since `CloudflareOptions` no longer declares it) or is merely ignored.
- Whether Cocoa's network breadcrumbs and `http.client` spans keep query strings; whether Android's `SentryInitProvider` (`auto-init`) does anything when the manifest carries no DSN.
- How many spans one 1 s reader poll produces end to end (client fetch span, Worker `http.server`, Hono middleware, Durable Object RPC, storage and SQL spans), which decides whether the [#381](https://github.com/patricktree/cup/issues/381) span budget holds.
- Bundle figures are the SDK repository's `size-limit` budgets, not measurements of Cup's bundle.
